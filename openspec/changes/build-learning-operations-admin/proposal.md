## Why

目前平台已能讓學員註冊、闖關與累積 XP，也能讓老師修改課程、查看學員名單；但後台仍停留在「看得到資料、整包覆寫內容」的展示階段，無法支援 UID 核對、卡關追蹤、來源成效、完課轉換、內容版本與異常處理。招生開始放大前，需要把後台升級成「學習營運中心」，讓負責人知道招來的人有沒有啟動、卡在哪裡、哪些來源有效，以及老師今天該先處理誰。

## What Changes

- 建立管理儀表板，呈現註冊、UID 核對、活躍、開課、完課、卡關與來源轉換等核心指標。
- 建立完整學員營運工作台：搜尋、篩選、詳情、UID 核對、備註、標籤、狀態、匯出與操作歷史。
- 建立課程草稿、預覽、發布、版本、回復與題目驗證流程，避免空白或錯誤內容直接影響全體學員。
- 建立學習事件與課程分析：每課開始、影片觀看、作答、通過、重測、卡關與掉隊漏斗。
- 建立來源成效分析，從 `trafficSource` 延伸到註冊、UID 核對、啟動、完課與進階資格。
- 建立營運待辦與告警，包括待核對 UID、長期未啟動、卡關、資料同步失敗與內容異常。
- **BREAKING**：以具名管理員帳號、角色與權限取代共用 PIN；舊 PIN 僅能作為短期遷移入口，不再是正式後台身分。
- **BREAKING**：將管理後台從單一 `index.html` 拆為獨立管理應用；學員前台可先保留現況，再逐步接入新資料模型。

## Capabilities

### New Capabilities

- `admin-dashboard`: 管理總覽、全域篩選、核心 KPI、漏斗、趨勢、待辦與下鑽。
- `student-operations`: 學員搜尋、篩選、詳情、UID 核對、備註、標籤、狀態、更正與匯出。
- `curriculum-publishing`: 課程草稿、驗證、預覽、版本、發布、回復與課程狀態管理。
- `learning-analytics`: 學習事件、課程漏斗、卡關、完課、留存、來源轉換與資料定義。
- `admin-access-control`: 管理員登入、角色、權限、停用、敏感操作確認與操作紀錄。
- `operations-settings`: XP／解鎖規則、來源、告警門檻、功能開關、資料品質與系統健康狀態。

### Modified Capabilities

目前沒有既有 OpenSpec capability；現有網站行為將由上述新規格接管。

## Impact

- 現有 `index.html` 的教師後台、學員同步、排行榜、課程儲存與 PIN 流程會逐步被替換。
- Firestore 需要從三個簡單集合擴充為學員、核對、課程版本、學習事件、管理員、角色、操作紀錄與聚合指標等資料模型。
- 建議建立獨立 Firebase 專案或至少獨立環境，避免繼續與 `airport-car` 共用正式資料邊界。
- 需要 Firebase Authentication、Firestore Security Rules、索引與伺服器端聚合／排程能力。
- 管理前端建議採可建置的獨立 SPA，學員前台與管理後台分開部署、分開授權。
- 現有本機學員 ID、進度與 XP 需要遷移或相容期；正式切換前必須有資料備份與回復方案。
