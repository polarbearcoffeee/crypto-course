## 6. 回滾窗口

白話說明：回滾是新版有嚴重問題時，暫停新功能並恢復到上一個可用版本。

目前尚未部署，因此回滾窗口**尚未開始，也尚未完成 Owner 核准**。建議候選方案如下：

- `T0`：第一個正式寫入功能啟用的時間。
- 回滾窗口：`T0` 至 `T0 + 7 天`，至少涵蓋一個完整日報核對週期。
- 窗口內保留：
  - 舊後台唯讀入口；
  - 可還原的正式資料備份；
  - 當前已發布課程版本指標；
  - 每個功能開關的前一版本；
  - 遷移批次與逐筆失敗清單。

建議回滾觸發條件：

- 權限失效、跨角色讀到不該讀的資料；
- 無法登入或無法撤權；
- 已發布課程內容錯誤且無法立即回復；
- 事件／XP／摘要核對不一致；
- 遷移出現資料遺失或不可逆覆寫；
- 核心錯誤率或延遲超過上線前核准門檻。

建議回滾順序：

1. 停止受影響功能的正式寫入開關。
2. 保留事件、請求編號、稽核紀錄與錯誤樣本。
3. 將課程／設定指標切回上一個已驗證版本。
4. 必要時使用已驗證備份還原至隔離環境，核對後再決定正式還原。
5. 保持舊後台唯讀，避免兩套系統同時寫入。
6. Owner 記錄回滾原因、影響範圍、時間與後續修復負責人。
