# 新後台整合回診紀錄

日期：2026-07-31
範圍：GitHub Pages 展示測試平台，不接正式 Firebase，不使用真實學員資料。

## 本輪目標

把舊後台仍有價值的操作全部收進新 React 後台，讓展示者只需要進入
`/crypto-course/admin/`，不必在新舊兩套後台之間切換。

## 已整合

| 項目 | 整合結果 | 展示資料保存方式 |
|---|---|---|
| 後台入口 | 新增 Owner 展示登入、登入狀態與登出 | `sessionStorage` |
| 課程內容 | 匯入舊版 6 堂課，支援標題、重點、XP、影片、門檻與狀態編輯 | `localStorage` |
| 測驗題庫 | 匯入舊版 18 題，每題可編輯題目、四個選項與正確答案 | `localStorage` |
| 學員營運 | 搜尋、工作佇列、UID 核准／補正／拒絕、學習狀態與內部備註 | `localStorage` |
| 資料匯出 | 目前篩選結果的 UTF-8 CSV | 瀏覽器下載 |
| 舊 PIN | 保留為遷移工具，可修改或標記停用 | `localStorage` |
| 相關連結 | 前台、新後台、直接路由、GitHub、Actions、Pages、OpenSpec、驗收文件 | 靜態設定 |

## 根因與治本方向

舊版以單一 HTML、共用 PIN 與瀏覽器直連 Firestore 實作；這種方式可快速展示，
但不能提供正式的身分驗證、欄位權限、稽核與多人一致資料。這一輪先治療「兩套後台
分散、功能找不到、展示流程斷裂」，正式營運的治本仍是 Firebase Authentication、
Firestore Security Rules 與可信任後端 API。

## 安全邊界

- 展示帳密不是祕密，不能保護正式資料。
- `localStorage`／`sessionStorage` 是目前瀏覽器內的小抽屜，不是伺服器資料庫。
- 不得輸入真實 UID、聯絡資料、正式憑證或其他個資。
- 正式上線狀態仍為 `NO-GO`，直到資料庫、登入、權限、備份、遷移與授權資安驗證完成。

## 回歸重點

1. 錯誤帳密不可進入後台，正確展示帳密可以進入並登出。
2. 課程清單固定包含 6 堂課、每堂 3 題，總計 18 題。
3. 學員 UID 狀態與內部備註可更新，重新讀取展示資料後仍存在。
4. 舊 PIN 可修改並標記停用，但畫面明確說明它不是正式授權機制。
5. GitHub Pages 建置後，學員前台與 `/admin/` 必須同時可開啟。
